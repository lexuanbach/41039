Syllabus Week 9 Week 10 Playground I/O Lab
Lab · Weeks 9 and 10

Read a file. Break it. Watch the exception travel.

One small program, in Java and in Python: open scores.txt, add up the numbers, print the total and save it to report.txt. Change what is in the file and how the program handles trouble, then step through it. Watch the read position, the call stack, the open file, the console and the output file change as it runs.

Things to try

Eight questions to answer with the lab

Each link sets up the lab. Predict what happens first (tick Predict first to hide the console), then step through and check.

  • 1 · Who stops the program?

    Line 2 is abc and main catches nothing. Which frames does the exception pass through, and what is the exit code? Then make main catch each exception and compare.

    Set it up →

  • 2 · The file nobody closed

    The program closes scores.txt with close() after the loop. Step to the end: which panel turns red, and why? Fix it with Automatic or close() in finally.

    Set it up →

  • 3 · Does finally run during a crash?

    Nothing catches the exception, but main has a finally. Is Done printed? Before or after the stack trace?

    Set it up →

  • 4 · Skip, don't stop

    A try inside the loop catches the bad line. Is Bad score ever printed now? What is the total, and is report.txt written?

    Set it up →

  • 5 · Nothing to close

    scores.txt does not exist. Try all three ways of closing: does any of them have something to close? Which line throws?

    Set it up →

  • 6 · One broad catch

    main catches any Exception. Switch between A word and Missing file: the program survives both, but can it still tell the user what went wrong?

    Set it up →

  • 7 · Written is not saved

    Step to the line that writes the total. Where is Total: 60 at that moment: in report.txt, or somewhere else? What moves it into the file?

    Set it up →

  • 8 · Same file, different answers

    The file says 1_000. Run it in Java, then in Python. Why can't you watch them side by side? Try Too big for int as well.

The animation is checked

The lab writes both programs from your choices and animates a model of them. Every choice, on every example file, has been run on a real JDK and on CPython, and the model prints the same output, raises the same exception and leaves the same report.txt. To see it for yourself, press Run it for real under the code. Your own file contents are checked live the same way.

First run is slow

A real run downloads a runtime the first time: a JVM for Java, CPython for Python. That takes a few seconds and needs a network connection. Stepping through the animation needs neither.

Small differences from Ed

Java here is compiled by the Eclipse compiler on a Java 8 runtime, and a stack trace in the browser says Unknown Source where a real JDK gives a line number. The stack traces in the animation show the line numbers a real JDK and CPython print, without the frames inside Java's own library. Ed is what counts for your marks; this is for experimenting.
