01 · Concepts

What you should take away

Six ideas, in the order the lecture covers them. Everything here comes from the Week 1 lessons on Ed.

1.1What a program is

At the simplest level, programming is telling a computer what to do. Once that meant writing the right sequence of zeroes and ones into memory. In 1954 John Backus developed FORTRAN, and the programmer could start caring more about what to do than exactly how.

Language design did not stop there — there are now thousands of languages, with hundreds in active use. The history of programming is the history of raising the level of abstraction.

1.2The three basic tools

Underlying every general-purpose language are three core concepts:

  • State — a way of managing what situation the program is in
  • Branching — choosing which code to execute, usually based on the state
  • Repetition — repeating a piece of code, controlled by some parameter

Add basic input and output and that is everything you need to build a general-purpose programming language. This is SLO1.

1.3Your first Java program

A Java program is a sequence of statements arranged into blocks. Blocks nest, and the top level is a class.

Two rules, not conventions

Java is case sensitive. bob ≠ Bob ≠ BOB ≠ BoB. This will cause most of your errors for the next two weeks. And the file name must match the public class name — public class Hello lives in Hello.java. Ed manages files for you, so you may not notice until you compile on your own machine.

1.4Variables, types and values

A declaration is a type followed by a name. Initialisation is the first assignment of a value. Assignment takes the value on the right and stores it in the variable on the left.

Read this out loud, right to left

In maths, x = 4 asserts that x and 4 are the same thing. In Java, x = 4; takes the value on the right and stores it on the left. That is why a = a + 1; is false as maths but completely routine as Java: take a + 1, put it in a.

Java has eight primitive types; in practice you will mostly use int, double, char and boolean. Every type is a promise about how big the value can get — an int runs out at 2,147,483,647.

Careful

7 / 2 is 3, not 3.5. Integer divided by integer gives an integer. Use 7.0 / 2 to get 3.5.

1.5The same ideas in Python

The feature lists of Java and Python are almost identical — object oriented, procedural, imperative, garbage collected. Only two rows differ, and they explain nearly everything else you will notice.

Executioncompiledinterpreted
Typingstaticdynamic

That is the whole program, because Python allows code outside of classes. Java requires everything to live inside one. Java's extra ceremony is not pointless — it buys the ability to detect certain errors before the program runs. The two languages made different bets, and neither is better.

Indentation is not decoration

Java delimits blocks with { and }, so formatting is cosmetic. Python uses the indentation itself. Use four spaces, let the editor do it, and never mix tabs and spaces — that produces errors which are invisible on screen. In Java bad indentation is ugly; in Python it is wrong.

1.6When things go wrong

There are three kinds of error, and only two of them tell you:

  • Compile-time errors — the compiler cannot compile your code. It tells you.
  • Run-time errors — the code compiles, then crashes while running. It tells you.
  • Logic errors — it runs perfectly and does the wrong thing. Nothing tells you.

A Java compile error tells you four things. Read them in order:

compile error
WontCompile.java:3: error: cannot find symbol
        System.out.println("Hi " + userName + " how are you?");
                                   ^

Which file → which line → what kind → which token (follow the ^). And cannot find symbol means you used a name I have never seen — almost always a typo, a missing declaration, or a capitalisation slip.

Two things that will save you

1. Turn on Line Numbers in the Ed editor settings — without them, WontCompile.java:3 tells you nothing. 2. Fix the first error, then recompile. One small bug often produces many messages; errors 2 through 14 are usually downstream of error 1.

Python puts the error type last, where Java puts it first. In a Python traceback, read the last line first.

Not a sign you are bad at this

Bugs are an unavoidable part of programming. Everyone gets stuck — the skill being built here is reading what the computer already told you.
