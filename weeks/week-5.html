01The ideas behind OOP

1.1A brief history

Object-oriented programming (OOP) is a broad family of ways to design programs, centred on one idea: bind data to the code that is allowed to manipulate it, in a single entity called an object.

Historically the idea grew, possibly ironically, out of the functional language Lisp in the late 1950s and early 1960s. Simula introduced many of the concepts still in C++ and Java — classes, dynamic binding, inheritance — with syntax close to Algol 60, which is why it reads fairly easily to a Java programmer. Smalltalk was designed as an OO language from the ground up and is often called the first “true” one, but Simula has had the greater effect so far — not least because Bjarne Stroustrup used it during his doctoral work and then built its ideas into C++.

The class concept allowed me to map my application concepts into the language constructs in a direct way that made my code more readable than I had seen in any other language.

Bjarne Stroustrup, A History of C++: 1979–1991, HOPL-II, 1993 — on writing his PhD simulator in Simula Portrait: Victor Zavyalov / ICPCNews, 2013 · CC BY 2.0

OOP became the dominant paradigm in the 1990s, with C++, the arrival of Java, and a software industry that needed modular, reusable, maintainable programs at large scale. Like any tool it can be used badly; used well, it is a very powerful way to build large software that can be extended without being rewritten.

Did you know?

Two Turing Awards in three years went to object orientation. The 2001 award went to Ole-Johan Dahl and Kristen Nygaard “for ideas fundamental to the emergence of object-oriented programming, through their design of the programming languages Simula I and Simula 67”; the 2003 award to Alan Kay for “leading the team that developed Smalltalk”, among other things. Both Stroustrup and James Gosling, Java’s creator, have named Simula as a major influence. Source: Wikipedia — Turing Award and Simula.

1.2The four pillars

“Object-oriented” covers anything whose fundamental unit is the object, but almost every OO language rests on four principles:

PillarWhat it means
EncapsulationData is enclosed in objects. That gives it context, and control over how it is accessed and changed.
AbstractionImplementation details are hidden from the outside. Two implementations that do the same job are interchangeable; users only deal with the abstraction.
InheritanceObjects can inherit properties from other objects, so subtypes exist, share what they have in common and differ only where they need to.
PolymorphismOne thing, many “shapes”: different implementations of the same method, objects with several types, type information abstracted away.

They are not completely separate — encapsulation enables abstraction, inheritance supports polymorphism, polymorphism supports abstraction. Under all four sits a vaguer but stronger idea, shared with the modular programming that came before OOP: any unit of a program should not have to care how the rest of the program works in order to work correctly.

1.4Abstraction — and we tested the claim

Abstraction says you should not have to care about the insides of something when they do not matter to what it does. A clockwork watch, a digital watch and a phone all present the time; you use them interchangeably whether there are gears inside or a connection to an atomic clock.

For code, that means the rest of a program should not have to change when an implementation does. The Ed lesson offers a second BankAccount that stores a float instead of cents, and says the lab program could “probably (I haven’t tested it)” use it unchanged. So test it. Same main, word for word; only the inside of BankAccount differs:

  1. main depends only on the names, parameters and return types of the constructor and the four public methods. Those are identical, so main compiles without a change.
  2. In the cents version this loop added exactly 1000 cents. Here each call does a float addition that changes nothing (line 34), so Bach’s balance never moves from 1000000.0.
  3. The field now holds dollars directly, as a float. Because it is private, no code outside the class could depend on it — which is why the swap is invisible to main.
  4. No conversion to cents. But 100.10f cannot be held exactly: the nearest float is 100.09999847…, which currentBalance later rounds back to the cent.
  5. Turns dollars into cents and rounds to the nearest whole number. Given a float, Math.round returns an int.
  6. The cast applies to the int from Math.round, so / 100 divides in float and keeps the cents. Without it, int division would drop them.
  7. Each subtraction and addition rounds its result to the nearest float. Near Linh’s 100 dollars those errors are far below a cent, and currentBalance rounds them away.

A Java float is an IEEE 754 32-bit number with only about seven significant digits, and near 1,000,000 the gap between one float and the next is 0.0625 — so adding 0.01 rounds straight back to where it started.

What abstraction does and does not promise

The swap worked exactly as abstraction says it should: main compiled and ran without a single change. What abstraction cannot do is make the new implementation correct. That is why the Java lesson suggests storing money as an int number of cents — and why “I haven’t tested it” is a sentence worth never leaving in your own code.

1.5Inheritance and polymorphism, briefly

Inheritance arrives properly in the next few lessons. In Java it comes in two forms, class-based inheritance and interfaces, and it does two jobs at once: a child class reuses its parent’s data and methods instead of reimplementing them, and a child can be treated as the same kind of thing as its parent.

Polymorphism comes in three basic forms:

  • Ad-hoc — the same method name applied to different parameter lists. You have used it constantly: it is Week 4’s overloading, and the reason System.out.println has ten versions.
  • Parametric — type information abstracted out, so code can store or move objects without caring much what type they are. Coming very soon.
  • Sub-type — an object can be treated as having the type of any of its parent classes. Also coming very soon.

02Classes and objects in Java

2.1The dot operator, said out loud

A piece of syntax you have been using quietly since Week 1: ., said “dot”. It takes the thing on its left and retrieves the member inside it named on its right.

CodeWhat the dots do
System.out.println("Hi")look in the class System for the class-level variable out (a PrintStream — Week 4, 3.3); in that object find the method println(String), and run it with "Hi"
sc.nextInt()go to the object that the variable sc refers to, find its method nextInt(), and run it with no arguments

A dot gives you either a value (reading a variable) or a method (which then runs straight away). Because an object variable holds a reference — Week 4, section 6.3 — the dot is sometimes called the dereference operator: it follows the reference to the object. Beyond that there is nothing special about it; it just gets things out of other things.

2.2Classes are templates for objects

An object is a construct that encapsulates data and offers methods to interact with it. An OO language needs a way to define objects — what data they hold, what methods they have — and Java is class-based (as opposed to prototype-based): a class is the template for its objects.

<access modifier> class <Name> {
    <data and methods>
}
  • Access modifiers are the ones you know from methods. Classes are almost always public for now — and each .java file can have only one public class, named the same as the file.
  • Class names follow the variable rules, but start with an upper-case letter: Scanner, String, BankAccount.

An empty class is perfectly legal, and occasionally handy as a placeholder to fill in later. Empty here has no access modifier at all:

  1. Only one class per file may be public, and the file must be named after it — Runner.java. It holds main, so this is where the program starts.
  2. The variable’s type is the class Empty. Java is case-sensitive, so Empty and empty are different names; by convention only the class starts with a capital.
  3. The class is only the template; new makes an actual object from it and gives back a reference, stored in empty. It works although Empty declares no constructor, because Java supplies a default one (section 4.2).
  4. With no public, Empty can share Runner’s file. Its body holds no data and no methods, yet the class is legal and usable as a type.
One class, one purpose

A class should have a single clear purpose: it models one entity in the system. What counts as one entity depends on the system, and gets clearer with practice — but it is usually obvious what does not belong. A class modelling a bank account should not also store the staffing details of a branch.

03static: the class itself

3.1One copy, shared by every object

Objects quickly become the main actors in a Java program, but the class is still a thing in its own right. Anything marked static lives on the class: it exists without any objects, and it is not copied into objects at all. Reach a static variable through an object and you get the one class-level copy that every object shares:

  1. The variable belongs to the class Silly itself. It is created and set to 10 before main even starts, with no object in existence, and it is never copied into objects.
  2. a and b refer to two separate objects, but Silly has no instance variables, so neither object holds a value of its own.
  3. The compiler uses only the type of a, Silly, to find the field — the one class-level value, still 10. The object itself plays no part.
  4. There is no “b’s value” to change: this assigns 30 to the single shared copy, exactly as Silly.value = 30 would.
  5. Now 30, although nothing was done to a: a.value and b.value are two names for one variable.
  6. ClassName.member says plainly that the variable is static. It needs no object at all: Silly.value works even in a program that never says new Silly().

The Java Language Specification: for a static field “there exists exactly one incarnation of the field, no matter how many instances (possibly zero) of the class may eventually be created”. If every object of a class should share one value, this is how; it is also how to define program-wide constants, as static final — like the pizzas array in Week 4’s pizza shop.

Legal, but misleading

a.value looks as though it belongs to a. It does not. Write Silly.value for static members, so the code says what is really happening.

04Constructors, this, and objects in memory

4.1What an object is, in memory

In Java all objects are created dynamically, so they always live on the heap (Week 4, section 6.3). A new object gets space only for the class’s non-static variables, plus a little bookkeeping. The methods, the static variables and everything else shared by all objects of the class are stored once, with the class — the JVM specification calls that area the method area, which stores “per-class structures such as the run-time constant pool, field and method data, and the code for methods and constructors”.

An object variable is then just a reference to where that data sits on the heap — which is exactly what made Week 4’s arrays behave as they did when passed to methods.

4.2new and constructors

You have written this line in every program that reads input:

  1. The type is the class Scanner and the name is sc. The variable will hold a reference to a Scanner object on the heap, not the object itself.
  2. new asks the JVM for enough heap memory for one Scanner, then runs a constructor on it. The whole expression’s value is the reference to the new object, which is stored in sc.
  3. The class name with an argument list chooses the constructor. System.in is the program’s standard input stream, so this is the Scanner constructor that takes an input stream, and the new object is set up to read from it.

Type, variable name, then an initialisation that creates an object on the spot. new tells the JVM to allocate the right amount of heap memory for a Scanner and run a special method called a constructor — here the one that takes System.in. A constructor is where the object’s data members are normally initialised and anything else it needs is prepared. It runs once per object, and always first.

public class <ClassName> {

    <access modifier> <ClassName>(<parameter list>) {

    }

}

  • Its name is the class’s name, so it is one of the few method names that starts with a capital letter.

5.1Roughly Java’s model

Python’s object model is roughly similar to Java’s: a class is a template, objects are instances of it, and the class itself is still a thing in the code, so data and functions can live on the object or on the class.

And since every Python variable is already a reference (Week 4, section 7.4), two variables can hold references to the same object and change the same object — exactly like the Java accounts in section 4.4.

A class is defined much as you would guess: class, a name, a colon, and indentation.

06Dunder methods and open doors

6.1“Dunder” methods

Python has methods with special names, surrounded by double underscores — hence “dunder”, also called magic or special methods. They connect a class to the built-in functions and operators of the language. __init__ is one: it hooks into object creation.

Another is __str__, the method str() calls — and print too — much like Java’s toString(). Each dunder has its own rules: __init__ may take extra parameters and returns nothing; __str__ takes only self and must return a string.

  1. Money(1250) makes a new object and calls __init__ on it, with self as the new object and cents as 1250. Keeping whole cents in an int avoids floating-point rounding.
  2. Called by str(), and so by print, whenever a Money must become text. It takes no parameter but self and must return a str.
  3. // is floor division, so 1250 // 100 is 12. str() turns the int into a string so + can join it to the others.
  4. % gives the cents left over (5 for 305), and the string method zfill(2) pads with leading zeros to two characters, giving 05 rather than 5.
  5. For a + b Python calls a.__add__(b): self is the left operand, other the right. It returns a brand-new Money, leaving both operands unchanged.
  6. print converts its argument with str(), which calls Money.__str__. Without a __str__ you would see something like <__main__.Money object at 0x…>.

At a simple level, a Python class’s attributes behave like a dict, and access is public by default — so other code can replace them, if it knows the names. Offered without further comment, from the Ed lesson:

A method replaced from outside the class, and a brand-new attribute bolted on at run time. The Java compiler would reject every one of these lines. Python lets you — which is precisely why you should not.

6.3How to stop (some of) that

Python gives you a way to discourage this. Unless you say otherwise an attribute is public. Start its name with two underscores and code outside the class can no longer reach it by that name:

  1. A class attribute whose name starts with two underscores (and does not end with two). Inside the class body Python stores it under another name — the last example in this section shows which.
  2. Outside the class nothing is renamed, so Python looks for an attribute literally called __priv_data, finds none, and stops with an AttributeError.

It works for methods too — but not for dunder methods, even though they look similar, because a dunder name also ends in two underscores:

  1. The name ends in two underscores as well, so Python does not rename it. It also breaks the __str__ rule by having no self: print(Foo()) would fail with a TypeError.
  2. Two leading underscores but not two trailing ones, so inside the class Python stores this method as _Foo__hidden.
  3. Looks up __str__ on the class and calls it with no arguments, which suits a method with no parameters.
  4. The lookup itself fails, before any call: the class has no attribute called __hidden, so Python raises an AttributeError.

Now look back at the error from the first example: Python itself suggests _Foo__priv_data. The two underscores do not make the attribute private in Java’s sense; inside the class, Python quietly renames it (“name mangling”), and the new name works from anywhere:

  1. Inside class Foo, Python rewrites __priv_data as _Foo__priv_data: one underscore, the class name, then the original name.
  2. The mangled name is an ordinary attribute name, so any code can use it. The renaming exists to avoid clashes with names in subclasses, not to stop access.

“Private” instance variables that cannot be accessed except from inside an object don’t exist in Python.

A single leading underscore (_spam) is the other convention, which the tutorial describes as marking a non-public part of the code; the Ed lesson calls this “protected” and leaves it for later. 07Enums

7.1Enumerated types

An enumerated type is a data type with a fixed, finite set of named values. There are many ways to implement one, but the goal is always the same: data of that type can only ever be one of the known values. They appear in most languages descended from Algol — Pascal, C, C++, C#, Java — and in Swift, Fortran, Lisp, TypeScript and every functional language with algebraic types.

The classic example: a standard deck has exactly four suits, so any question about a card’s suit must be answered with one of those four, and nothing else.

7.2Enums in Java

enum <Name> { [<VALUE_NAME> [, <VALUE_NAME>]*]; }

The keyword enum, a name (capitalised like a class), then a comma-separated — possibly empty — list of value names ending in a semicolon. By convention the values are in capitals, like constants. An enum can be declared on its own or inside a class. A value is reached as Suit.HEARTS, like a field, and every enum has a values() method that works with the for-each loop:

  1. The keyword enum declares a new type, Suit, whose values are exactly the ones listed. Declared inside Cards, it can be used anywhere in the class, like any other type.
  2. Capitals by convention, as for constants, with a semicolon after the list. The order written here is the order values() hands them back in.
  3. Declared like an int or String variable, but it can hold only a Suit. The value is reached through the type’s name, like a field; trumps = 3; would not compile.
  4. Joining a value to a string calls its toString(), which by default gives the value’s name exactly as declared, SPADES.
  5. Every enum has a values() method that returns a Suit[] holding all its values in declaration order — just what the for-each loop needs.
  6. There is only ever one SPADES object, so comparing references with == correctly answers “is this the same suit?” (section 7.3).
  7. If the comparison is true, the bracket’s value is " <- trumps"; otherwise it is the empty string, so only the trumps line gets the arrow.

Did you know?

Before Java 5, the standard way to write an enumerated type was a row of int constants: public static final int SEASON_WINTER = 0; and so on. The Java 5 release notes list what was wrong with it, starting with “Not typesafe” — any int could be passed where a season was expected, and two seasons could be added together. Enums fixed that by making each set of values a type of its own. Source: Oracle — Enums (J2SE 5.0 guide).

7.3== is safe on enums

Java enums are implemented as a special kind of class: think of a class with a fixed number of pre-declared objects — the values. You cannot create more (or fewer) of them, so you never need a constructor call, and there is exactly one object for each value. The Java Language Specification: “An enum class has no instances other than those defined by its enum constants.”

So, unlike the accounts in section 4.4, comparing with == works as you would naively expect — for enums, .equals gives the same answer as comparing references, because there are never two copies of the same value.

7.8And in C, just numbers

For comparison: an enum in C is a set of names for the numbers 0 to (number of values − 1), assigned automatically. That keeps the key property — a fixed set of distinct values — but not Java’s type safety: underneath, it is just an int.

  1. C numbers the names automatically, in order: HEARTS is 0, SPADES 1, DIAMONDS 2, CLUBS 3. They are plain int constants, used with no Suit in front.
  2. In C the type is called enum Suit, both words, every time it is used. Declared outside any function, s is a global variable, which C starts at 0.
  3. SPADES is the number 1. C would accept s = 42; just as happily — nothing ties s to the four suits, which is the type safety Java’s enums add.
  4. %d prints an int in decimal, and s is one underneath, so out comes its number rather than a name. C has no built-in way to turn an enum value back into its name.

08Advanced switch

Weeks 2+3 taught the switch statement: equality only, fall-through, and break. Java has since added three things: switch expressions, pattern matching, and when clauses. All three need a newer Java than this page’s console — section 8.2 shows exactly what happens if you try — so most examples here are static, with their real output from a current JDK. Run them on Ed, which uses Java 23.

8.1Stretching the old switch

A plain switch only tests equality, but careful choice of the expression you switch on can stretch it. This runs anywhere, including here:

  1. The Scanner method nextInt reads the next whole number typed and returns it as an int, ready to switch on.
  2. Works out the expression in brackets once, then jumps to the case whose value is equal to it. That single calculation is the only work done before choosing.
  3. % gives the remainder after dividing by 2, which is 0 for every even number. Switching on it turns “is n even?” into an equality test, the only test a plain switch can do.
  4. Matches only when n % 2 equals 0 exactly. A plain case label must be a constant, so a condition such as case n > 0: is not allowed.
  5. Jumps out of the switch. Without it an even number would fall through into the default code and print both lines (Weeks 2+3, section 3).
  6. Runs when no case matched. It is better than case 1: here: for a negative odd number, n % 2 is −1 in Java, and default catches that too.

But the only computation happens once, in the switch’s own expression. The newer features let each case do some of the work.

8.3Switch expressions

A switch expression is like a switch statement, except that each case produces a value. The syntax changes to case … -> <value>;: an arrow where you would expect a colon, and no break. The switch hands back the value after the arrow and is finished — no fall-through, much as a return ends a method. And because it produces a value, it can go anywhere an expression can (Weeks 2+3, section 1.2):

  1. Here the switch is an operand of +: it produces a String, which is joined to "The number is ". A switch statement could never stand in this spot.
  2. If n % 2 is 0, the whole switch has the value "even" and is finished: no break, and no fall-through into the next case.
  3. A switch expression must be exhaustive, and an int has far more values than 0, so default is required. Replace it with case 1 and javac reports that the switch expression does not cover all possible input values.

Did you know?

8.4Pattern matching and when

Pattern matching lets a case examine the type and structure of the value being switched on, and give it a name. A when clause then narrows a case to a sub-case with any boolean condition:

  1. nextLine returns a String, which an Object variable can hold. Declared as Object, n could in principle be anything, so the switch has to find out what it is.
  2. The old switch accepted only a few types, such as int, char, String and enums. With pattern matching (Java 21) it can switch on any object.
  3. Matches if n is a String and, if so, names it s, with type String, for this case only — so String methods can be called on it.
  4. Narrows the case: it matches only if the boolean condition after when is also true. length() returns the number of characters, 0 for an empty line.
  5. Colon cases still fall through, so the breaks stay. Leaving this one out is a compile error: javac will not let execution fall through into a case that declares a pattern variable like s.
  6. Every String the first case did not take lands here. Put this case first and javac refuses the program, since the guarded case could never match: this case label is dominated by a preceding case label.
  7. A switch that uses patterns must cover every possible value, and n could be any Object. Remove the default and javac says the switch statement does not cover all possible input values.

You have seen this idea in Python

Python’s match (Weeks 2+3, section 4.3) has the same thing, called a guard: if after the pattern. And unlike the Java above, it runs in this page’s console:

  1. Shows the prompt, waits for a line and returns what was typed as a str, without the newline. Pressing Enter alone gives the empty string ''.
  2. Tries each case pattern against name, top to bottom, and runs only the first that matches. There is no fall-through and no break.
  3. A bare name matches any value and binds it to s — like Java’s case String s, but with no type check.
  4. Python’s version of when: the case matches only if this condition is also true. len gives the number of characters, 0 for an empty line.
  5. With no guard this pattern matches anything, so it must be the last case — Python rejects any case after it with a SyntaxError. It does the job of Java’s default.

8.5Record patterns, _, and a switch with no default

A tantalising hint of how far this goes, using a record from Week 4:

  1. A name and a mark, with a constructor and component methods written for you. Because its components are known, a pattern can take it apart again.
  2. The parameter is an Object, so grade accepts a Student or anything else; the switch works out which it got. Line 25 passes it luke.
  3. The switch produces a String, and return hands it straight back. The ; after its closing brace on line 16 ends the return statement.
  4. Matches if o is a Student and deconstructs it: the mark component goes straight into a new variable mark, with no need to write mark().
  5. Cases are tried in order, so a mark over 100 is caught here, before mark >= 85 on the next line could claim it.
  6. The name component must be listed to match a Student’s shape, but grading never uses it, so it gets the unnamed variable _ (Java 22) instead of a name.
  7. Reaching this case means the mark is neither over 100 nor 85 or more, so >= 75 here really means 75 to 84 — just like an else if ladder.
  8. No when, so it matches any Student still left: by now, any mark below 50, negative ones included.
  9. Matches any object at all, so together the cases cover every possible value of o. The switch is exhaustive, as a switch expression must be, with no default.
