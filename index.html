01 · What this subject covers

Three ideas, then how to organise them

Weeks 2, 3 and 5 deliver the three concepts every general-purpose program is built from. Add input and output and you can write any program at all. Everything from Week 6 adds no fourth idea — it is about keeping those three manageable as programs grow.

Part 1 · Weeks 1–5

The three basic tools

State, decision and iteration — plus the input and output that connect a program to the world. This is SLO1, and it is the whole foundation.

  • Simplest working program & output
  • Data types & variables
  • Decisions & branching
  • Arrays & user input
  • Loops & iteration
Part 2 · Weeks 6–12

Organising bigger programs

No new primitives — just structure. Classes, methods, lists, files and inheritance are all ways of keeping state, decision and iteration under control at scale.

  • Classes & constructors
  • Methods, properties & access control
  • Lists & polymorphism
  • File input and output
  • OO techniques & structures
  • Inheritance & interfaces
Why two languages

Python shows you an idea with the least ceremony. Java shows you what that ceremony buys — types checked before the program runs, and errors caught at compile time rather than in front of a user. Seeing the same concept in both is the fastest way to tell a language feature apart from a programming idea.

02 · Subject learning outcomes

By the end of the session, you can

Write programs

  • SLO1 — Apply the basic programming concepts of state, iteration and decision
  • SLO2 — Solve computational problems using abstract modelling
  • SLO3 — Design and create simple functioning programs

Explain programs

  • SLO4 — Interpret, describe and document programs clearly
  • SLO5 — Reflect on programming decisions and formulate alternatives
Read this twice

Writing code is 55% of the marks. Explaining and reasoning about code is 45%. Students who treat this as a subject about typing code are consistently surprised by the other half.

Lab assessments

Exercises most weeks, marked automatically. Unlimited attempts — attempt 1 and attempt 101 score the same — but you must pass every test case in an exercise to get its marks. Due 11:55pm the Monday of the following week.

25%

Code comprehension

Four in-person orals, about three minutes each, run during lab classes. You are given a short piece of code and asked about it. The questions are released beforehand.

25%

Project

One program of roughly 500 lines, built progressively across the session. The only assessment touching all five SLOs, and the only one where you design the structure yourself.

20%

Exam

Take-home, open-book, one day. Tests understanding and application, not recall.

Code comprehension · four stages

Stage 1 in Week 4 (5%) · Stage 2 in Week 7 (5%) · Stage 3 in Week 11 (7%) · Stage 4 in Week 12 (8%). Timetabling permitting — confirm on Canvas.

Optional · 0% · Extension

Challenging free-form problems, sometimes requiring research beyond the subject. Worth 0% by itself, but can substitute for the lab assessments. Worth considering if the weekly exercises feel easy.

Academic integrity

All submitted code is analysed by similarity tools that examine how code works, not how it looks — renaming variables does not help. Researching a concept or an error message is encouraged and expected. Submitting code you cannot explain is not, and four times this session you will be asked to explain code out loud, in person. Reported cases go to a committee, not to teaching staff, and can take months to resolve. Ask for help early instead.
